# 범종과 기록 보호 — 첫 구현

이 기능은 기존 방공호 사찰 공간에 구형 보호 장치를 추가한다. 지상 범종각·대자비 감시·레이저·퍼즐·결말·시와 일기는 변경하지 않는다. 지상 범종각의 종 단면을 활용한 작은 종을 방공호 `[-5, 0, -9]`에 배치했다. 이산의 기존 배회 경로와 겹치지 않는다.

## 작동 규칙

- PC: 장치 가까이에서 E 또는 기존 클릭 상호작용. 모바일: 장치 탭 또는 행동 버튼.
- `recordProtection.ts`의 설정: 보호 8,000ms, 재사용 대기 20,000ms. 대기는 작동 시작부터 계산하므로 보호 종료 후 약 12초가 더 남는다.
- 같은 보호 구간과 대기 중에는 다시 눌러도 연장되지 않는다.
- 최종 행동 호출 시 `시작 <= 실행 시각 < 종료`로 판정한다. 창을 열었던 시각으로 보호를 예약하지 않는다.
- 판정은 단조 시계 `performance.timeOrigin + performance.now()`를 사용하며 프레임·표시 타이머에 의존하지 않는다. 설정창·다른 탭에서도 시간은 흐른다.
- 장치는 방공호에만 적용된다. 종소리를 재생하는 `sfx.gong()`은 보호를 활성화하지 않는다.
- 시작은 종소리·초록 표시·남은 시간, 종료는 짧은 알림음·명시적인 꺼짐 표시로 구분한다. 음소거에서도 작동과 판정은 같다.

## 데이터 책임

| 데이터 | 저장·처리 |
| --- | --- |
| 기존 게임 진행 | `sanlee-visited` 등 기존 경로를 유지. 보호 중에도 터미널 진행은 저장됨 |
| 기존 재개·백업 | `sanlee-backup` 형식을 그대로 유지. 보호 상태나 활동 내용을 추가하지 않음 |
| 시민 활동 기록 | 신규 `sanlee-citizen-records-v1`, schema 1. `pending`은 방공호 오프라인 기록, `synced`는 세계관 속 중앙에 반영한 기록 |
| 보호 장치 상태 | 현재 문서의 메모리에만 존재. 작동 사용 사실·보호된 행동·공백 항목을 시민 기록에 저장하지 않음 |

실제 서버나 중앙 감시 서비스로 보내지 않는다. 이번 단계의 동기화는 클라이언트 내부 데이터 이동이다. 지상 진입 때 기존 `pending`만 `synced`로 이동하며 반복해도 복제되지 않는다. 게임 진행·백업으로부터 시민 기록을 재구성하지 않으므로 보호된 행동은 재접속·동기화로 되살아나지 않는다.

현재 연결된 실제 행동은 잠금 검사를 통과한 터미널 열람 `terminal.open`이다. 최종 동작에서 `recordCitizenActivity({kind, sourceId}, {zone, unregistered})`를 호출한다. 새 퍼즐은 만들지 않았으며 추후에도 제출 버튼의 최종 실행 지점에서 이 인터페이스를 사용하면 된다. 진행 저장은 이 함수와 별도 경로로 처리해야 한다.

`forgetCityRecords()`는 기존 도시 기록과 함께 신규 시민 기록 키·캐시·보호 장치 메모리를 비운다. 언어·소리·조작 설정은 유지한다. 기존 `wipeBackup()`의 의미는 바꾸지 않았다. 따라서 단순 복원이나 기존 재시작 동작으로 시민 기록을 되살리거나 임의로 삭제하지 않는다.

## 개발용 확인

`/deleteseoul?debug&fx=off`로 진입하면 기존 디버그 도구에 다음이 추가된다. `fx=off`는 기존 품질 비교 옵션이며 일반 플레이에는 필요 없다.

```js
__neo.recordProtection.snapshot()
__neo.citizenRecords.read()
__neo.citizenRecords.commit("manual-final-action")
```

마지막 호출은 테스트용 시민 행동의 최종 실행을 모사한다. 반환 상태는 `recorded`, `protected`, `unregistered`, `full`이다. 보호 중에는 시민 기록 키나 배열이 바뀌지 않아야 한다. 이 호출은 게임 진행을 바꾸지 않는다.

직접 확인할 순서:

1. 보호 밖에서 터미널을 열고 pending 기록을 확인한다.
2. 종을 치고 상태 표시를 확인한다. 한 번 더 눌러도 종료 시각이 늘어나지 않는지 확인한다.
3. 8초 안에 다른 터미널을 연다. 게임 진행은 저장되지만 시민 기록에는 추가되지 않아야 한다.
4. 패널을 읽고 있다가 보호 종료 후 최종 테스트 행동을 실행하면 일반 기록으로 추가되어야 한다.
5. 기존 정상 진행으로 지상에 올라가면 보호 밖 기록만 synced로 이동해야 한다.
6. 새로고침 후에도 보호된 내용이 없어야 한다.
7. 기존 푸터 삭제를 실행하면 시민 기록과 메모리가 함께 비워지고 설정은 남아야 한다.

## 자동 검증

제공된 Node.js 24 환경에서:

```sh
node --test --test-reporter=spec tests/*.test.mjs
./node_modules/.bin/tsc --noEmit --incremental false
npm run build
```

이미 Playwright·Chromium이 제공되는 환경에서만 선택적으로 브라우저 검증을 실행한다. 새 라이브러리를 설치하지 않았다.

```sh
npm run start -- --hostname 127.0.0.1 --port 3010
node tests/bell-protection.browser.cjs
```

`BELL_TEST_BASE_URL`과 `CHROMIUM_PATH`로 실행 위치를 바꿀 수 있다. PC·모바일 에뮬레이션, 소프트웨어 WebGL, 기존 디버그 이동을 이용한다. 실제 타종은 UI 입력으로 실행한다. 실제 iPhone/Android 기기 검증을 대신하지 않는다.

## 남은 범위

- 보호·대기는 문서 메모리에 있어 새로고침하면 초기화된다. 서버 권한·치트 방지 기능이 아니다.
- 단일 탭 기준이다. 다중 탭의 동시 기록·삭제 및 캐시 일관성은 후속 설계가 필요하다.
- 기록 용량은 합계 512건으로 제한한다. 가득 차면 과거 기록을 버리지 않고 새 기록에 `full`을 반환한다.
- 저장 공간 부족·브라우저 저장 차단 시 메모리에서 계속 동작하지만 새로고침 후 보존은 보장되지 않는다.
- 실제 모바일 오디오 정책과 기본 그래픽 품질의 발열·프레임률은 별도 기기 확인이 필요하다.
