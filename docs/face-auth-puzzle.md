# 퍼즐 A — 얼굴을 맞추십시오

기준: `feat/bell-record-protection`, `b265d456738e5faeed7d2827c29f3b1adf246b07`.
원격에 얼굴 퍼즐 브랜치가 없었고 현재 체크아웃에는 변경·stash·도달 불가 Git 객체가 없었다. 이전 offline 환경의 미푸시 파일은 확인할 수 없다.

## 구현과 저장

- `faceAuth.ts`: 버전 1 진행 상태, 입력 검증, 해법별 조건, 보호 만료 재확인 판정, 후속 카메라용 `faceConsequences`.
- `FaceAuthPanel.tsx`: 등록/현장 비교, 스캔, 보정 미리보기, 클릭으로 자료 선택·제출, 준비와 최종 실행 분리.
- `FaceAuthObjects.tsx`: 전용 단말 `[-3,-5]`, 스캐너, 검사등, 명세판, 정면·측면 관찰 자리.
- `ExploreClient`, `World`, `Bunker`, `Statue`: 기존 구조 안에서 연결, 얼굴 부분 복원과 제한된 고개/눈/입 표현. 방문 횟수가 새 퍼즐의 얼굴 복원을 대신하지 않는다.
- 기존 세 터미널은 유지한다. 신규 플레이에서는 추가 인증이 구현될 때까지 얼굴 인증과 세 터미널만으로 이산이 걷거나 지상에 나가지 않는다. 기존 3개 터미널 완료 저장은 `legacy` 호환 경로로 기존 동행을 보존한다.
- `sanlee-face-auth-v1`: method, prepared, scanner, scan, front, side, specs, preview, slots, lampDim, portrait, legacy. 보호 사용 이력은 이 키에 저장하지 않는다.
- 시민 기록은 기존 `sanlee-citizen-records-v1`에 최종 `face.authenticate`만 기록한다. 보호 중에는 기록 없이 진행만 저장한다. 보호가 끝난 제출은 사용자 재확인까지 중단한다. 기록 API에서 실행 시각을 다시 확인해 경계 시점도 보호한다.
- 기존 도시 기록 삭제 동작은 새 진행 키도 함께 삭제한다. 백업 데이터 형식, 실제 작품·시·일기, 대자비 코드는 변경하지 않는다.

## 플레이 경로

1. `/deleteseoul`에 들어가 지하 중앙 받침대 정면의 청록 고리에서 관찰한다.
2. 받침대 오른쪽 스캐너를 머리 높이로 올린다. 측면 고리에서 윤곽도 관찰할 수 있다.
3. 받침대 남서쪽 얼굴 인증 장치에서 현장 스캔을 실행한다.
4. A: 표준 보정 미리보기 → 표준 보정 준비.
5. B: 장치 옆 명세판 조사 → 단말에서 현장 스캔 자료 선택 후 현장 결과 칸 제출 → 명세 자료 선택 후 등록 기준 칸 제출 → 대조 오류 증명 준비.
6. 보호 없이 최종 실행하거나, 준비 후 창을 닫고 범종 `[-5,-9]`을 친 다음 단말로 돌아와 최종 실행한다.
7. 보호 종료 후 실행하면 안내를 읽고 기록을 남기는 실행을 명시적으로 선택하거나 취소한다.
8. 새로고침 후 단말에서 결과와 머리 부분 복원을 확인한다. 검사등과 원본 자화상 감상은 선택 사항이다.

PC E/클릭, 모바일 기존 행동 버튼/장치 탭을 이용한다. 실측 이동 속도는 코드상 걷기 3.4m/s이며 종→단말 직선 약 4.5m다. 브라우저 자동 테스트는 디버그 이동으로 상호작용을 검증하므로 실제 모바일 조이스틱 이동 시간의 증거는 아니다.

## 검증과 한계

- Node 24: `node --test --test-isolation=none --test-reporter=spec tests/*.test.mjs` (28개 통과).
- `./node_modules/.bin/tsc --noEmit --incremental false` 통과.
- `node tests/face-auth.browser.cjs`: Playwright/Chromium 필요. 두 해법, PC/모바일, 보호 중 인증 및 재접속 확인. 결과는 현재 실행 로그를 따른다.
- 기존 `tests/bell-protection.browser.cjs`: PC 회귀 통과. 모바일 실행은 초기화 대기 시간 초과로 미검증.
- `/` 및 `/deleteseoul` 개발 HTTP 응답 확인. 개발 서버는 Google Fonts 차단 시 대체 폰트를 사용한다.
- 정식 Turbopack/webpack 빌드는 기존 Google Fonts 다운로드의 HTTP 403 정책 차단으로 실패했다. 폰트 도메인 두 개를 환경 초안에 요청했다. 미확인 빌드를 성공으로 취급하지 않는다.
- 실제 iPhone/Android, 조이스틱 이동 시간, 대자비/엔딩의 전체 플레이 회귀, 시각적 감정 연출의 최종 검수는 남아 있다. 3D 장치와 얼굴은 간단한 도형 기반이며 정교한 시각 완성도는 추가 검수가 필요하다.
- 이번 작업은 실제 얼굴 인식, 추가 인증 B/C, 지상 카메라 행동, 신규 엔딩을 구현하지 않는다.
