# DELETE SEOUL — 3D 재구축: 1차 플레이어블 시제품

작성: 2026-11-04 · 작업 브랜치: `feat/delete-seoul-rebuild-3d-v1`

## 원칙

- **기존 1인칭 3D를 유지**한다. 2D 전환은 하지 않는다.
- 과거 A·B 퍼즐은 새 이야기의 선행 조건이 **아니다**. 기존 3D 공간/장치는 테스트용 장소와 소품으로만 재활용한다.
- **기존 공개 경로 `/deleteseoul`은 건드리지 않는다.** 이 브랜치의 실험판은 `/deleteseoul-lab`이다. 검색 색인은 차단한다.
- 2026년의 창작자 이산이 디지털 자화상을 만들었다. 2087년은 작품의 내부 시간이며, 현실의 61년짜리 서버 실행 또는 과거-미래 실시간 통신으로 설명하지 않는다.
- 게임 속 이산은 창작자와 다른 경험을 가진 인물. 무명사는 관객이 브라우저 밖에서 기록을 초기화할 수 있음을 알고 이를 숨긴다.
- 대자비는 외부 관객의 접근을 막는다. 플레이어가 중앙 단말에 가는 이유는 이산의 부탁을 그대로 수행하려는 것이 아니라 **삭제 범위의 진실을 확인하기 위해서**다.
- 실제 삭제는 로컬 브라우저의 **v2 실험판 저장 키 하나만** 지운다. 서버의 게임 코드, 타인의 기록, 기존 A/B 저장은 삭제하지 않는다.

## 첫 시제품 루트

| 단계 | 3D 상호작용 | 결과 |
| --- | --- | --- |
| arrival | 중앙 이산 조사 | 복원 요청 |
| recovery | 얼굴 장치 자리에 놓인 원본 조회 | 제작 연도 2026, 디지털 자화상 암시 |
| origin | 기록 장치 조회 | 조작된 동의 기록, 이산 격리 해제 |
| restored | 보증 장치를 관리 단말로 재사용 | 원본 제작자·배신 계획 발견 |
| discovered | 이산에게 재접근 | 그가 플레이어를 기다린 이유, 비고지 사실 |
| confronted | 지상 출구 | 대자비로 가거나 떠나기 |
| crossing | 기존 대자비 엄폐·레이저를 통과 | 검문소의 삭제 범위 확인 |
| decision | 중앙 단말의 선택 | 기록 보존 또는 작품 밖으로 이동 |
| erased (outside) | `/deleteseoul-lab/erase`에서 실제 삭제 버튼 | v2 기억 초기화; 재접속 시 새 게임 |

기억 반응은 R-07 친구, 아이의 그림, 무전수의 소리, 스님의 단서 네 가지로 시작한다. 도덕 점수나 여러 개의 복잡한 퀘스트 분기는 만들지 않는다.

## 실행 및 검수

1. 작업 브랜치 배포에서 `/deleteseoul-lab?fx=off` 접속. 기본 3D 탐험이 가능한지 PC와 모바일에서 각각 확인.
2. 이산 → 원본 자화상 장치 → 기억 보관 장치 → 관리 단말 → 이산 추궁 → 지상 출구로 진행하는지 확인. 기존 A/B를 풀지 않아도 진행되어야 한다.
3. R-07과 친구가 되어 놓고 배신 뒤 다시 대화하면 반응이 달라지는지 확인.
4. 지상에서 시선 게이지, 엄폐, 레이저, 충돌 후 재시작이 동작하는지 확인. 패널·결정 화면에서 공격이 진행되지 않아야 한다.
5. 검문소 기록 목록에 **실제로 선택한 관계만** 나오는지 확인.
6. 기록을 남긴 뒤 새로고침하여 보존되는지 확인. 저장 공간이 차단되어도 현 세션은 충돌 없이 동작해야 한다.
7. 작품 밖 삭제 화면에서 삭제 후 재접속해 상태가 초기화되는지, 기존 `sanlee-face-auth-v1` 등은 그대로인지 확인.
8. 테스트 후 기존 `/deleteseoul`의 A·B 및 기존 엔딩 동작에 회귀가 없는지 확인.
9. MacBook Air M1/16GB에서 `?fx=off`와 기본 그래픽 설정의 FPS를 비교해 최적화한다.

## 이 단계에서 아직 하지 않은 것

- 방공호의 물리적 무명사 리디자인
- 인물 대사 연기·음악·컷신 최종본
- 20~25분에 맞는 탐험 깊이와 맥락 있는 선택 확장
- 새 게임의 자동화된 브라우저 E2E와 성능 테스트

현재 구현은 **서사와 3D 동선이 연결되는지 보는 기능성 시제품**이지 최종 완성본이 아니다.
